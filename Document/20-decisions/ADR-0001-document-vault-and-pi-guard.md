# ADR-0001: 문서 Vault와 Pi 작업 확인

**상태:** 승인됨

## 결정

`Document/` 자체를 플러그인 없이 열 수 있는 Obsidian Vault로 사용한다. `Graph-PI-Desktop`의 주제별 번호와 인덱스 구조를 참고하되, 현재 지식을 담을 영역만 연다. `Home.md`에서 관련 노트를 찾고, 장기적으로 참고할 지식이 달라졌을 때만 메인 에이전트가 관리한다.

신뢰된 저장소 루트에서 프로젝트 로컬 확장이 로드된 Pi는 작업 시작 시 최신 `Home.md`를 시스템 프롬프트의 한 섹션에 넣는다. 읽지 못하면 해당 작업의 모델 도구 호출을 차단한다. 정상적으로 도구를 실행한 작업은 종료 전에 기록 필요성을 한 번 확인한다. 실제로 무엇을 남길지는 메인 에이전트가 판단하고, 확장은 Vault에 쓰지 않는다.

## 이유와 대안

- 지침 파일만으로는 진입 노트 읽기 실패 시 모델 도구 실행을 차단할 수 없다. 프로젝트 로컬 확장을 쓰면 개인 설정을 바꾸지 않고 지원 범위에서 이를 확인할 수 있다.
- 진입 노트를 대화 메시지로 매번 붙이면 과거 본문이 쌓인다. 작업마다 시스템 프롬프트의 한 섹션을 갱신하면 오래된 사본을 별도로 추가하지 않는다.
- 작업마다 일지를 자동 생성하면 기록할 지식이 없을 때도 파일이 바뀐다. 한 번 확인하되, 변경 여부는 메인 에이전트가 판단한다.

이 차단은 확장이 로드된 메인 Pi의 모델 도구에 한정한다. 외부 셸, 다른 에이전트, 하위 세션의 독립 실행이나 확장을 로드하지 않은 세션에는 적용을 보장하지 않는다.
