# ADR-0003: 전투 기반과 GAS 채택

- 상태: 채택
- 관련: [캐릭터 이동과 자세](../30-design/character-movement.md), [전투 시스템](../30-design/combat-system.md), [조작과 전투 규칙](../30-design/controls.md)

## 맥락

차원 데모까지는 폰(`ADemoPawn`)이 `APawn` + `FloatingPawnMovement`로 WASD와 카메라만 처리했다. 전투를 붙이려면 네 가지를 먼저 정해야 했다. (1) 체력·피해·능력을 무엇으로 관리할 것인가, (2) 이동을 기존 폰에 얹을지 `ACharacter`로 올릴지, (3) 총구 벌어짐 같은 연출 수치를 어디에 둘 것인가, (4) HUD를 C++로만 그릴지 위젯 블루프린트를 둘지.

차원 전환(Q/E 2초 홀드)은 이미 동작하며, 새 전투가 그 위에서 함께 돌아야 한다.

## 결정

1. **GameplayAbilitySystem을 정식으로 도입한다.** `Client.uproject`에 플러그인을 켜고 `Client.Build.cs`에 `GameplayAbilities`, `GameplayTasks`, `GameplayTags`를 추가한다. 체력은 `UCombatAttributeSet`(`Health`, `MaxHealth`), 피해는 GameplayEffect, 발사·재장전은 `UGameplayAbility`로 둔다. 사격 쿨다운(0.15초)과 재장전 시간도 GAS의 쿨다운·지속시간으로 표현한다.
2. **이동은 `ACharacter`로 승격한다.** `CharacterMovementComponent`가 점프·앉기(캡슐 높이 전환)·공중 제어를 기본 제공하고, 구르기는 커스텀 무브먼트 모드가 아니라 속도·중력·입력 잠금 조합으로 처리한다. 기존 `ADemoPawn`은 `ACombatCharacter`로 대체하고, 차원 데모 컨트롤러·게임모드는 같은 레벨에서 그대로 쓴다.
3. **연출 수치는 단일 설정 구조체에 모으고, 계산은 순수 함수로 분리한다.** 상태별 최대 벌어짐·추종 속도, 점프 충격, 탄퍼짐, 반동 값은 `UCombatConfig` 같은 데이터 객체 한 곳에 두고, 벌어짐 계산은 시간·상태·입력만 받는 순수 함수(`ComputeMuzzleDeviation`)로 뺀다. 자동 테스트가 월드 없이 곡선을 검증할 수 있고, 문서 표와 코드 값을 대조하기도 쉽다.
4. **HUD는 C++ 위젯 클래스 + 생성한 위젯 블루프린트를 함께 쓴다.** `UUserWidget` 파생 클래스에 `BindWidget`으로 `UProgressBar`(즉시 바), `UProgressBar`(지연 바), 데미지 숫자 컨테이너를 선언하고, `WBP_HUD`·`WBP_HPBar`·`WBP_DamageNumber`는 에디터 자동화로 만들어 클래스에 연결한다. 위젯 트리는 C++ 계약이 정하고, 색·크기 같은 표현만 블루프린트에서 조정한다.
5. **투사체는 기본 도형 + `ProjectileMovementComponent`로 만들되, 판정은 스윕으로 한다.** 속도 8000/s에서 한 프레임 이동 거리가 벽 두께보다 클 수 있어, 매 틱 이전 위치에서 현재 위치로 스윕해 벽·캐릭터를 건너뛰지 않게 한다.
6. **타격감은 코드로 처리하고 에셋을 최소화한다.** 히트스톱은 `GlobalTimeDilation`을 0.06초 내렸다 반드시 복원하고, 셰이크는 `UCameraShakeBase` 파생 클래스, 파티클은 기본 도형 기반 임팩트로 처리한다. 사운드는 `USoundBase*` 훅만 둔다.

## 대안과 이유

- **GAS vs 단순 C++ 체력/쿨다운**: 단순 구현은 파일이 적고 빌드도 빠르다. 그러나 이 프로젝트는 이후 능력·버프·차원별 효과를 붙일 계획이고, 그때 체력·피해·쿨다운을 다시 뜯어고치면 이미 만든 UI·투사체·테스트가 전부 영향을 받는다. GAS는 초기 비용(플러그인, AttributeSet, GE/GA 배선)이 크지만 피해 경로가 한 곳으로 모여 확장 시 재작업이 없다. 기술 스택 문서가 이미 GAS를 계획으로 적어 둔 것도 같은 판단이다.
- **`ACharacter` 승격 vs 커스텀 폰 유지**: `APawn` 유지 시 점프·앉기·바닥 판정·경사 처리를 직접 구현해야 하고, 그 코드는 엔진이 이미 검증한 것과 같은 일을 다시 하는 코드가 된다. 승격 비용은 폰 클래스 교체와 레벨 배치 갱신뿐이다.
- **벌어짐을 데이터 테이블 애셋 vs C++ 기본값**: 데이터 테이블 애셋은 리디자이너가 에디터에서 고치기 쉽지만, 문서·코드·애셋 세 곳이 어긋날 수 있다. 이번에는 C++ 기본값 + 문서 표로 두고, 자동 테스트가 "문서 표 == 코드 기본값"을 검사해 어긋남을 빌드 단계에서 잡는다. 값이 자주 바뀌면 그때 데이터 애셋으로 옮긴다.
- **UMG 블루프린트만 vs C++ 계약 + 블루프린트**: 블루프린트만 쓰면 바인딩 이름이 리네임에 취약하고 자동 테스트가 위젯 구조를 확인할 수 없다. C++ 클래스에 `BindWidget` 계약을 두면 이름이 어긋날 때 컴파일·생성 단계에서 실패한다.
- **히트스톱 `GlobalTimeDilation` vs 개별 액터 슬로우**: 전역 배율은 구현이 한 줄이고 화면 전체가 멈춰 타격감이 크다. 대신 UI 애니메이션까지 같이 느려지므로 지속 시간을 0.06초로 짧게 잡고 반드시 복원한다.

## 결과

- 피해·체력·쿨다운이 GAS 한 경로로 모여, 이후 능력 추가 시 UI·투사체를 다시 만들지 않아도 된다.
- 이동 규칙이 엔진 기본 위에 얹혀 점프·앉기·경사·공중 제어의 미묘한 버그를 직접 만들지 않는다.
- 문서 표와 코드 값이 어긋나면 `node tools/pi/check_combat_docs.mjs`가 실패해 기획과 구현이 조용히 갈라지지 않는다.
- 폰 클래스가 바뀌므로 기존 레벨의 폰 배치·게임모드 기본 폰 설정을 함께 갱신해야 한다.

## 알려진 한계

- 히트스톱은 전역 시간 배율을 쓰므로, 지속 시간이 길어지면 UI·차원 전환 연출까지 느려진다. 이번 값(0.06초)에서는 눈에 띄지 않지만, 이후 히트스톱을 길게 쓰려면 개별 액터 단위로 바꿔야 한다.
- 구르기에는 피격 면역이 없다([조작과 전투 규칙](../30-design/controls.md)의 기존 규칙). 구르기 중 피격되면 그대로 피해를 받는다.
- 차원 전환 시 지오메트리 끼임은 [ADR-0002](ADR-0002-dimension-level-authoring.md)의 한계가 그대로 남아 있다. 전투 중 전환하면 같은 문제가 발생할 수 있다.
- 사운드는 훅만 있고 실제 소리는 나지 않는다.
