# ADR-0002: 차원 레벨 저작 방식

- 상태: 채택
- 관련: [레벨 명세: 오피스 데모](../30-design/level-office-demo.md), [차원 시스템](../30-design/dimension-system.md)

## 맥락

차원 시스템은 레벨의 액터가 현재 차원에 따라 보이거나 사라지는 것을 전제로 한다. 첫 레벨을 만들기 전에 두 가지를 정해야 했다. (1) 차원 소속을 어디에 저장할 것인가, (2) 레벨을 무엇으로 저작할 것인가.

기술 데모라서 아트 애셋을 쓸 수 없고, 엔진 기본 도형만으로 공간 구조와 차원 차이를 읽을 수 있어야 했다.

## 결정

1. **차원 소속은 액터 태그에 둔다.** `Dim:A|B|C`, 태그가 없으면 모든 차원 공통, `DimGroup:<name>`은 형태 전환 그룹이다. `UDimensionSubsystem`이 전환 시 태그를 훑어 `SetActorHiddenInGame`과 `SetActorEnableCollision`을 적용한다.
2. **레벨은 에디터 Python 스크립트로 생성한다.** `tools/unreal/build_office_demo.py`가 재질·지오메트리·조명·PlayerStart·네비게이션을 만들고, `tools/unreal/verify_office_demo.py`가 규칙을 검사해 실패 시 0이 아닌 코드로 끝난다. 생성물은 `Generated:OfficeDemo` 태그로 구분해 재실행 시 지우고 다시 만든다.
3. **차원 반응 메시는 네비게이션에서 제외한다.** `can_ever_affect_navigation=False`로 두어 정적 네비게시를 한 번만 베이크한다. 전환할 때마다 네비메시를 다시 만들면 비용이 크고, 차원 전용 통로가 런타임에 내비게이션을 바꾸는 문제도 생긴다.
4. **노출을 고정한다.** 차원별 스크린샷을 같은 조건에서 비교하려면 자동 노출을 끄고 EV100을 고정해야 한다.

## 대안과 이유

- **액터 태그 vs 별도 데이터 애셋**: 데이터 애셋은 레벨과 동기화가 깨지기 쉽고, 액터를 옮길 때 같이 고쳐야 한다. 태그는 액터에 붙어 있어 복제·병합·아웃라이너 필터에서 그대로 따라온다. 단점은 태그 문자열이 코드·스크립트 양쪽에 흩어진다는 것이라 접두사를 `Dim:`으로 고정하고 파싱을 한 곳(`DimensionTags`)에 모았다.
- **태그 vs 레벨별 하드코딩**: 하드코딩은 레벨이 늘 때마다 코드가 늘어난다. 태그 규약은 레벨 추가에 코드 변경이 필요 없다.
- **스크립트 생성 vs 손으로 저작**: 손 저작은 재현이 안 되고 리뷰에서 차이를 확인할 수 없다. 스크립트는 좌표를 텍스트로 남겨 리뷰·수정이 쉽고, 실패를 검증 스크립트로 자동 판정한다. 단점은 형태가 단순해져 아트 레벨의 완성도는 낮다는 것이다.
- **콜리전까지 끄는 전환 vs 시각만 전환**: 시각만 바꾸면 차원 전용 벽을 통과할 수 있어 차원 차이가 의미를 잃는다. 그래서 보임과 콜리전을 함께 전환한다.

## 결과

- 레벨에 차원을 추가할 때 코드 변경 없이 태그만 붙이면 된다.
- 검증이 실패하면 `inventory.json`의 `failed`에 이유가 남아 회귀를 바로 잡을 수 있다.
- 태그 문자열이 규약이므로 오타는 조용히 "공통 액터"가 된다. 검증 스크립트가 차원별 액터 수를 세어 0개인 차원을 실패로 처리하는 이유다.

## 알려진 한계: 전환 시 지오메트리 끼임

전환은 플레이어 위치를 검사하지 않는다. 새 차원에서 켜지는 벽이나 엄폐물이 플레이어와 겹치면 플레이어가 지오메트리 안에 끼인 채로 남는다. 기획 문서는 "전환 직후 겹치면 전환하지 않고 실패 피드백을 준다"고 정했지만, 이번 데모 범위에서는 전환 실패 처리와 밀어내기를 구현하지 않았다. 데모 레벨은 차원 전용 벽을 통로에만 두어 실제로 겹칠 확률을 낮췄을 뿐, 문제를 해결한 것은 아니다. 정식 레벨을 만들기 전에 전환 전 겹침 검사(플레이어 캡슐과 새 차원 콜리전의 스윕)와 실패 피드백을 먼저 구현해야 한다.
